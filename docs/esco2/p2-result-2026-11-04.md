## Design and source boundary

The chosen representation retains `ResultadoParte` and the necessary semantic
sidecar, with deterministic factual rendering. This is a bounded labor change,
not a new query framework or a five-domain acceptance result.

The changed runtime is the single-source labor core in `src/utils/esco2/` and the
actual HTTP `supabase/functions/esco-consultas/manejador.ts`. It now supplies:

- Source-state and value/reference validation before filtering; unread, null,
  explicit zero and verified empty remain distinct. Unavailable application or
  task metadata does not erase available labor. Raw dates must be real calendar
  dates; they are not repaired by slicing malformed input.
- Stable task/lot/type grouping and resolved selector IDs, inclusive Bogotá
  calendar intervals, Monday weeks, recorded-work versus planned-start cohorts,
  explicit ranking metric/direction/ties, full totals and truncation disclosure.
- Disjoint with-lot/sin-lote partitions from the same selected records, with
  exclusions disclosed. Correct existing ratio and work-date calculations remain.
- D30 whole-task estimates with known subtotal, recorded-null and unread-estimate
  counts; duplicate type labels cannot combine unrelated ID groups.
- Deterministic factual blocks and closed headings. Normal substantive turns
  make one planner call and zero composer calls. The deployed model configuration
  values are unchanged. Numeric-membership guards no longer certify factual prose.
- A disposition for every original multipart obligation, including independent
  answers while another part needs clarification. Client history cannot resolve
  D26/D29 or authorize scope.

The API accepts `estadoToken` and an exact `respuestaAclaracion` choice ID, never
client-owned typed state. The process-local store binds opaque random tokens to
the verified authenticated user, with a 15-minute TTL, 200-entry maximum and
64-KiB UTF-8 state limit. Choices freeze IDs/canonical categories and revalidate
references; empty intersections fail safely. Unrelated replies retain pending
state; foreign, expired or orphaned choices cannot select scope. Oversized state
preserves independent results and requests a narrower question without truncating
identities. A restart, eviction or another instance can lose context; no durable
conversation guarantee is claimed. The browser clarification UX was not built or
certified by this backend slice.

The CTO found existing local authority for task assignment in `tareas.lote_ids`:
the task editor writes it directly and migrations 021/022/033 consume it.
Null, absent and an explicit empty array carry different meanings. Migrations
005/008 stop application-to-task lot synchronization after registered work.
Thus planned-start selection describes the task's stored lot assignment and
current state; it does not certify current application targets or historical state.
No production schema/data inspection was performed.

Separate Supabase reads cannot establish an atomic cross-table snapshot.
Answers retain this consistency limit rather than certify strict cross-table
reconciliation. No new consistent-read RPC, migration or snapshot was acquired.
