# Local request-contract repair candidate

This candidate remains local. It has not been published, merged or deployed.
Its source baseline is main `a635a05e7f6c466dd75b140658850ef2e5091a1e`
(the controls merge after the v294 runtime). Online outcomes and their original
grades are unchanged. Local synthetic tests do not establish online acceptance.

## Four mechanisms repaired together

1. **Requested parts versus proposed tool arguments.** Application presentation
   metrics come from the current USER request, independently of a valid but wrong
   model metric. Status, dates, recorded quantities, recorded labor and explicitly
   requested theory remain distinct. Progress retains the existing status/date/
   quantity/labor operation; it does not authorize theory. Negated fields stay
   excluded. A definition cannot hide another requested application-data part.
   A bounded retry preserves already verified text even if a later round fails.
2. **Aggregate labor contract.** The offered schema and reader normalization share
   one closed contract. It offers no personal filter. Unknown/personal arguments,
   including a personal field set to null, are invalid arguments before source
   reads. Optional empty lot filters are absent, not a different population.
   Grouping by lot is separate from naming a lot. A proposed partial name needs
   a unique fresh-catalog match backed by USER selector syntax. Unknown or
   ambiguous selectors clarify rather than widening. Historical row costs are
   still summed independently of journal fractions and global averages.
3. **Definition versus record claim.** Pertinent explanations of registered
   application states use the existing fixed semantic text without requiring a
   record identity. A definition does not assert the state of an individual
   record, physical completion, quality or cause. Other-domain, negated and
   quoted examples do not grant a definition operation.
4. **One bounded USER scope chain.** Up to six chronological server-read USER
   messages can resolve a continuation. Missing IDs/timestamps, contradictory
   selectors or an unresolved link do not skip backward to another identity.
   The original USER anchor and current identity assertions remain server-side
   for fresh catalog binding. No raw selector, anchor, assistant answer or old
   source values are reinserted into the model payload. The current explicit
   lot can replace a prior lot only after fresh binding; ID/name/type conflicts
   and negative population selectors clarify. The operational period comes from
   the resolved current scope, not the anchor's old date.

Application and general-labor clauses have separate period and selector ports.
A purchase activity word cannot grant an application-type filter. Strong clause
boundaries and explicit new requests delimit the supported mixed forms. Useful
verified parts survive errors; an unqueried requested domain is shown as pending.
This is not a general natural-language entailment or unrestricted date parser.

## Preserved boundaries

- Same selected catalog, access policy and existing Web/Telegram gates. No new
  personal fields, permissions, credentials, provider or data recipient.
- Same three-round maximum. Mutation proposals on an operational query are denied
  without a corrective retry that could execute them.
- Registered, derived, planned and theoretical facts remain distinct. Unknown
  fields and partial populations are not zeros. No physical-success inference.
- Cohort receipts still independently verify membership. Blocked continuations
  are not evidence of an additional receipt defect. No new KV/schema/storage.
- No capture, Telegram conversation, weighing, webhook or business-write changes.
- Existing one-time release pins and guards are unchanged; they do not authorize
  this candidate. A later reviewed release must bind its actual source and fresh
  recovery proof. Native file counts are not inferred from reconstructed counts.

## Regression evidence

Tests use synthetic source records and closed model/HTTP transport. They inspect
the offered schema, complete outbound model payload, actual reader requests,
persisted safe context and final server-composed response. Matrices include:

- Correct, omitted, invalid, valid-but-wrong and subset metric proposals;
  independent mixed clauses; explicit exclusions; progress and consumption.
- Equal journal quantities with unequal historical costs; null/zero, incomplete
  counts and source failure; grouping modifiers and partial/duplicate lot names.
- General state explanations, unrelated definitions, and a definition followed
  by missing-data retry, terminal failure or bounded fallback.
- Chained/non-prefix references, current-period replacement, month boundaries,
  invalid history, ID/name conflicts, wrong ID class, current lot replacement,
  exclusions and a cost record outside the requested period.
- Contaminated synthetic USER/assistant/tool/memory history, privacy and full
  channel-handler gates, and existing capture/weighing tests.

The closed HTTP replay stays exact. Its payload pins changed solely because the
offered aggregate labor schema changed; a test restores just the old schema and
recovers both old hashes. Source queries, seeded factual contradiction, scoring,
unknown-request rejection and unused-fixture checks are unchanged.

No production records, conversations, oracle payloads, screenshots, credentials
or model calls were used to build this patch. The manifest consists solely of
repository code, synthetic tests, synchronization code and this document.

## Limits and next gate

Clause/domain grammar and conservative clarifications remain bounded. Source
pagination is not an atomic snapshot. Local handler tests are not real Deno boot
or live Telegram capture. No new online improvement is claimed. Final complete
test/type/lint/build results and the exact local commit are reported separately;
publication and release wait for the parent's final campaign classification and
review of the coherent batch.
