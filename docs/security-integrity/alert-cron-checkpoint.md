Observed source boundary: the tick reads configuration, subscriptions, derived animal state, pending steps and open alerts in separate requests, then directly generates/retires/delivers/escalates/expires alerts. Implementation contract:

- Protect job reservations, immutable transitions/audit and frozen delivery bodies in a private namespace. Capture a consistent configuration/subscription/recipient/animal/clinical/event/alert source, trusted server reference time and stable original job key. Source changes refuse atomically rather than overwriting a newer human result. Generation and retirement/escalation/expiration decisions must be bound to that original source and the reviewed server rule engine.
- Scheduled actor is the actual service-role job principal, without invented human profile. Manual reservation must use the initiating JWT and fresh active Gerencia; service execution preserves that verified initiator and rechecks authority. Ordinary clients must not submit arbitrary generation/message plans as trusted job output. No new live secret is created or changed.
- Commit alert mutations, exact before/after audit and frozen per-recipient outbox rows in one transaction. Reserve stable alert/delivery IDs. Identical-key retry/status recovers the original proof; it does not regenerate a plan from newer facts or allocate a replacement delivery after uncertainty.
- Grant permission to physically send a queued delivery once. A repeated or uncertain claim must never grant send permission again. The actual sender performs one HTTP request and classifies confirmed accepted message ID, definite rejection, or unknown outcome. Unknown includes transport loss, malformed success and ambiguous server errors. Rate limits never cause a bypass or unbounded immediate retries.
- Recheck current target/config/subscription/registration/linked-profile authority before granting a send. Record a later observed outcome even if a human changed the alert in flight, but never overwrite that newer alert state. Retry settlement/status of the original delivery rather than sending again. Unresolved claimed/unknown deliveries remain visible and cannot silently become delivered or safely retryable.
- Independent original private callbacks may provide fresh evidence of a specific frozen delivery only when its recipient, native message action and current registration/binding match. Ambiguous legacy sends are not adopted as prospective outbox proof. The existing prepared clinical/alert response protocols remain responsible for domain effects; a notification callback is not proof of clinical execution.
- Keep existing historical alerts and message IDs intact. Release still requires actual cron/browser/bot caller parity, a combined native fault/race replay, ordinary-role/runtime checks and coherent recovery. Local synthetic transport is not hosted Telegram/webhook or scheduler certification.
